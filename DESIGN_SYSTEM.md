## Issues found in current system (flagged, not yet fixed — waiting on page-by-page go-ahead)

1. **Two design eras coexist.** Original card-based system (purple accent,
   system sans-serif) + a newer "Chats" system (serif display font,
   orange accent, added later — comment literally says "New light
   'Chats' design system"). Result: `history.html` and `profile.html`
   feel visually different from `login.html`/`onboarding.html`/`settings.html`.
   This is the single biggest "does this feel handmade by one team"
   red flag — will raise as a real conversation once we're in a screen
   that touches it.
2. **No defined spacing scale.** Padding/margin values are ad-hoc:
   6, 8, 10, 11, 12, 13, 14, 16, 18, 20, 22, 24, 26px all appear without
   a system (not a clean 4/8pt grid).
3. **No defined type scale.** Font sizes in use: 0.7, 0.72, 0.76, 0.78,
   0.8, 0.82, 0.85, 0.86, 0.88, 0.9, 0.92, 0.94, 0.95, 0.98, 1.05, 1.15,
   1.5, 2rem — 18 distinct sizes for what should be ~6-7 step scale.
4. **Box-shadows repeated inline** rather than as tokens — same
   shadow recipe (`0 6px 18px -12px rgba(60,60,120,0.25)` /
   `0 20px 40px -20px rgba(60,60,120,0.18)`) copy-pasted across cards.
5. **No dark mode / color-scheme handling** — single fixed light palette.
6. **`--accent-orange` is a one-off** — used only for the FAB
   (`history.html`). Two accent colors with no defined relationship
   (secondary CTA? alert? just decoration?) is a smell.

None of these are being touched yet — listing them here so decisions
are visible and I don't "rediscover" the same issue on every page.

## Reusable components already in shared CSS (extend these, don't reinvent)
- `.card` — base elevated container
- `button.primary` / `button.secondary` — form actions
- `.chip` / `.chip-group` — selectable option list (onboarding)
- `.page-loader` — centered async loading state (documented as reusable in the CSS itself)
- `.collapsible-panel` — expand/collapse detail section
- `.drawer-*` — hamburger nav
- `.profile-row` / `.profile-*` — icon-label-value rows
- `.commit-mode-*` — Commit Mode banner + disclosure modal

## Mobile/Capacitor constraints already respected in current code
- `.wrap` caps width at 480px, uses `100dvh` — good practice already in place.
- `back-nav.js` — Android hardware back-button handled per-page.
- `html, body { overflow:hidden; overscroll-behavior:none }` — prevents
  browser-chrome bounce/scroll artifacts inside the WebView.

## Log of changes made through this project

### settings.html

#### Follow-up bugfix: Report/Resume button text getting clipped
- **Reported**: a word inside the action row looked "half cut off." Root cause traced (not guessed): `.wrap` (shared base rule) sets `overflow:hidden` on *both* axes; history.html's page-level override only reset `overflow-y:auto`, silently leaving `overflow-x:hidden` in effect. Separately, `.chat-card-actions` uses `display:flex` with no `flex-wrap` (defaults to `nowrap`), and `.report-btn`/`.resume-btn` were `flex:1` but had no `min-width:0` — per the flexbox spec, a flex item's default `min-width:auto` prevents it shrinking below its content's own minimum (the width of its longest single word, e.g. "Generate"). So on a narrow device, or with the OS's "larger text" accessibility setting bumping the 0.85rem font up, both buttons' combined minimum width could exceed the available row width; the row overflowed, and the inherited `overflow-x:hidden` silently clipped that overflow at the edge instead of wrapping it — producing the exact "word cut in half" symptom, with no scrollbar or other visible sign anything was wrong.
- **Fix**: added `min-width:0; line-height:1.25;` to both `.report-btn` and `.resume-btn`. This lets each button shrink properly under width pressure, so on a tight layout the label wraps onto a second line inside the button (which grows slightly taller) instead of overflowing and getting clipped. Nothing about `.wrap`'s `overflow-x:hidden` was touched — that's an intentional app-wide safety net against accidental horizontal scrollbars, and correctly hiding it is the right call *once* the actual content no longer needs more space than it's given, which this fix addresses at the source.
- **Also investigated and confirmed NOT a bug**: "all cards show the mic icon except one showing the person icon." Traced `session_type` end-to-end — `chat.html`'s `persistLocalSession()`/sync payload never sends a `session_type` field at all for freeform sessions, while `scenario.html` explicitly sends `session_type: 'scenario'`. `isScenario = s.session_type === 'scenario'` in history.html therefore only ever matches actual scenario sessions — this is the icon logic working exactly as designed from the earlier structural-rebuild pass, not a regression. Flagged back to product owner to confirm the one "person icon" session really was created via scenario.html (expected) rather than being a freeform chat that got mistagged (which would be a data issue, not a UI one).
